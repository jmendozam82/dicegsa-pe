# ADR-016 — El navegador nunca consume la API interna; el MVC hace de proxy con `IApiClient`
**Fecha:** 2026-09-30 · **Estado:** Aceptado · **Autor:** @Arquitecto / Jorge (Dicegsa)

## Contexto

La solución despliega la API (`PE-GOL.API`) y el MVC (`PE-GOL.Aplicacion`) en **origenes distintos** (`https://localhost:7269` y `https://localhost:7200` en local; `Api:BaseUrl` fija el absoluto que consume el `ApiClient` C#). El principio del repo desde HU-045 (ADR-009) es que **el navegador habla con el MVC y el MVC habla con la API** — el `ApiClient` con JWT en sesión es el puente diseñado para eso.

**Falló en HU-023** (Defecto E, Revisión v3): `plan-consolidado.js:14` declara `var API_BASE = '/api/v1/planes/consolidado'` — una ruta **relativa al origen del MVC**. El navegador acaba pidiendo `https://localhost:7200/api/v1/planes/consolidado` → **HTTP 404**, porque el proyecto MVC **no tiene ninguna ruta `/api/v1` ni proxy alguno** (`Program.cs` solo hace `MapControllerRoute` de MVC). Verificado en vivo: `:7200/api/v1/planes/consolidado` → 404 · `:7200/api/v1/planes/consolidado/exportar` → 404 · `:7269/api/v1/planes/consolidado` → 200 (con JWT de `Gerente`) · `:7269/api/v1/planes/consolidado/exportar` → 200. **Alcance del daño:** la tabla inicial se ve bien (render server-side del MVC), pero **ninguna interacción del usuario funciona** — los `fetch` de `obtenerConsolidado()` (L92: filtros y paginación) y `exportarExcel()` (L128) están ambos rotos. Síntoma: `alert('Error al cargar los datos: Error 404')` (`plan-consolidado.js:315`).

**Ningún test C# lo detectó ni puede detectarlo** (los de `PlanControllerTests` mockean `IApiClient` — nunca ejercitan una URL construida en JS); salió en la **validación visual en navegador** del hotfix de HU-023 (2026-09-30) — misma clase de defecto runtime que AGENTS.md v1.25 documentó para HU-021. **Precedente del repo:** `wwwroot/js/gantt-plan.js` (HU-021, validado en navegador) **no hace ningún `fetch`** — su vista documenta literalmente «no hay form GET, no hay AJAX y no se vuelve a llamar a la API»; los datos se renderizan server-side. `plan-consolidado.js` es hoy el único fichero de `wwwroot/js/` que usa `API_BASE`; `entregables.js` (HU-022) tiene 3 `fetch` en ruta relativa (L225/372/401) — **mismo defecto**, fuera de alcance (ver Consecuencias).

## Opciones consideradas

1. **Proxy por acciones MVC con `IApiClient`** — el JS llama a acciones del controller MVC (rutas relativas al MVC, autenticadas con la cookie de sesión) y estas proxean la API con el `ApiClient` (JWT en sesión), que ya existe y ya es el puente diseñado para eso. Elegida por Jorge: es la única opción **consistente con el patrón del repo**.
2. **Inyectar `Api:BaseUrl` al JS** (el JS construiría la URL absoluta de la API) — descartada: obliga a habilitar **CORS** entre MVC y API y **expone el JWT cross-origin en el navegador** (el token tendría que viajar en el header de peticiones del navegador a otro origen) — vector de seguridad nuevo y excepción al patrón de sesión del repo.
3. **Renderizar todo server-side como HU-021/Gantt** (sin `fetch`: cada filtro/paginación recarga la vista) — descartada: una **reescritura grande** de la vista que **mueve la paginación al navegador**, perdiendo la paginación server-side de la HU.

## Decisión

**Opción 1: proxy por acciones MVC con `IApiClient`.**

- **Regla:** el navegador **nunca** consume la API interna. Si una vista necesita datos de la API en interacciones del usuario, se añade una **acción MVC proxy** que llama a la API con `IApiClient` (JWT en sesión) y devuelve la respuesta al JS. El navegador se autentica con la **cookie de sesión del MVC**; el JWT no viaja en peticiones del navegador.
- **Aplica a HU-023** (Defecto E): 2 acciones nuevas en `PE-GOL.Aplicacion/Controllers/PlanController.cs` — `GET /Plan/ConsolidadoDatos` (proxea `GET /api/v1/planes/consolidado` reenviando los filtros del query string y devuelve el payload JSON) y `GET /Plan/ConsolidadoExportar` (proxea `GET /api/v1/planes/consolidado/exportar` y devuelve `FileResult` binario). `plan-consolidado.js` elimina `API_BASE` y sus 2 `fetch` pasan a esas rutas relativas al MVC. Contrato completo (query string permitido, `FileResult`, errores) en `specs/sprint-04/HU-023.spec.md` «Revisión v3».
- **Contrato de errores del proxy (obligatorio):** ante `ApiClientException`, los detalles internos (ruta absoluta de la API, JWT, header `Authorization`) van **solo al log del servidor**; al navegador llega el **mismo código HTTP** con un body `{ message, errors }` — los mensajes **user-facing de la API** (`ex.Message`/`ex.Errors`, diseñados para mostrarse — ARCH-07) **sí viajan**, para que las validaciones 422 (p. ej. «máximo 5 archivos por acción») lleguen al usuario y sepa qué corregir (UX-04); el cuerpo de la respuesta **nunca** contiene el JWT, el header `Authorization` ni la URL interna (`Api:BaseUrl`) — regla dura blindada por test. Precisión registrada al cerrar el hotfix de HU-022 (2026-10-01): ver `specs/sprint-04/HU-022-hotfix.spec.md` § B.3 (matriz de errores) y Decisión D-4.
- **`entregables.js` NO se toca en HU-023**: su corrección es un hotfix propio de HU-022 (ver Consecuencias).

## Consecuencias

- **Positivo:** el JWT deja de exponerse en peticiones cross-origin del navegador (refuerza SEC-01/SEC-05); se elimina la dependencia de CORS en esta vista; el patrón del repo queda cerrado y uniforme (el `ApiClient` con JWT en sesión es el único puente hacia la API, siempre vía MVC).
- **Trade-off:** cada vista con interacciones que necesitan datos de la API gana acciones proxy en su controller MVC (más código server-side) y un salto extra de latencia (navegador → MVC → API).
- **Deuda técnica registrada (pagada el 2026-10-01 por el hotfix de HU-022):** `entregables.js` (HU-022) tenía el **mismo defecto E** — 3 `fetch` en ruta relativa contra el MVC (`:7200`) en **L225, L372 y L401** → 404. Fix: proxy MVC `/AccionPlan/EntregablesDatos` con `ApiClient`. Era **hotfix propio de HU-022**, no incluido en el hotfix de HU-023 — registrado y localizado en `docs/HANDOFF_PE_GOL.md` «Deuda técnica pendiente», ítem 3. **Pagada:** el hotfix de HU-022 (`specs/sprint-04/HU-022-hotfix.spec.md`) implementó los 4 proxies `/AccionPlan/EntregablesDatos|Subir|Descarga|Eliminar` y vació `ExcepcionesConocidas` en `JsApiBaseUrlRegressionTests` — el scan de `wwwroot/js/*.js` queda limpio.
- **Regla operativa para @QA y @BackendDev:** si una vista necesita datos de la API, se añade una **acción MVC proxy**; un `fetch` a `/api/v1/...` en `wwwroot/js/` es un **defecto** (ruta relativa al origen del MVC → 404; o, si se inyectara el origen de la API, JWT cross-origin). Ningún test C# puede detectarlo (los mocks de `IApiClient` no ejercitan URLs construidas en JS) — la validación visual en navegador (Jorge) es el gate final de toda vista con JS.
