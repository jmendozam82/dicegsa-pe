# Spec HU-019 — CRUD de Acciones del Plan
**Sprint:** 3 · **Épica:** EP-06 · **Pts:** 8 · **Estado:** Implementado

## Contexto
Backlog `03_BACKLOG.md` L913. 
**Como** JEF  
**Quiero** crear, editar y eliminar acciones dentro de cada Objetivo CG de mi área  
**Para** desglosar cada objetivo en pasos concretos con fechas y responsables.

## Endpoints
| Método | Ruta | Auth | Descripción |
|---|---|---|---|
| GET | `/api/v1/objetivos-cg/{objetivoCgId:guid}/acciones` | `JefeArea, Gerente` | Lista las acciones de un Objetivo CG. |
| GET | `/api/v1/acciones/{id:guid}` | `JefeArea, Gerente` | Obtiene el detalle de una acción. |
| POST | `/api/v1/objetivos-cg/{objetivoCgId:guid}/acciones` | `JefeArea` | Crea una nueva acción en el Objetivo CG. |
| PUT | `/api/v1/acciones/{id:guid}` | `JefeArea` | Actualiza la información de una acción. |
| DELETE | `/api/v1/acciones/{id:guid}` | `JefeArea` | Elimina una acción (en cascada silenciosa para entregables/historial). |

> **Nota de acceso:** El patrón es usar `[Authorize(Roles = "JefeArea,Gerente")]` en el Controller y re-validar los permisos a nivel BLL según RN-007.

## Validaciones FluentValidation (`AccionPlanRequestValidator`)
- `Descripcion`: `NotEmpty()`, `MaximumLength(1000)`.
- `Clasificacion`: `IsEnumName(typeof(ClasificacionAccion))` (Proyecto, Iniciativa, Operativa).
- `TipoPresupuesto`: `IsEnumName(typeof(TipoPresupuesto))` (OPEX, CAPEX).
- `FechaVencimiento`: Debe ser `>= FechaInicio` (RN-019).
- `Peso`: `GreaterThan(0)`, `LessThanOrEqualTo(1)`.

## Lógica BLL (paso a paso)

### `CrearAsync(objetivoCgId, request)`
1. Validar que exista el Tenant en el contexto.
2. Validar que el `objetivoCgId` exista y pertenezca al `TenantId`.
3. Validar Rol (RN-007): Si es `JefeArea`, verificar que el `area_id` del `objetivo_cg` coincida con el `AreaId` del contexto.
4. Obtener el ciclo asociado al objetivo CG para validaciones de fechas.
5. Calcular año fiscal (RN-021): la `FechaInicio` y `FechaVencimiento` deben estar dentro del periodo del ciclo (`MesInicio` y `AñoFiscal` durante 12 meses).
6. Validar suma de pesos (RN-016): Consultar la suma actual de pesos de las acciones del `objetivoCgId`. Validar que `suma_actual + request.Peso <= 1.0`. Lanza `BusinessException` si supera 1.0.
7. Calcular correlativo: `nuevo_orden = max(orden) + 1` de las acciones del objetivo.
8. Generar código: `codigo = {objetivoCg.Codigo}.{nuevo_orden:D2}`.
9. Insertar entidad con `progreso = 0`, `status = 'NoIniciado'`, `puntuacion_ponderada = 0`.
10. Retornar `AccionPlanResponse`.

### `ActualizarAsync(id, request)`
1. Validar Tenant y obtener la acción por `id`.
2. Validar Rol: Si es `JefeArea`, verificar que su área coincida.
3. Validar ciclo de fechas igual que en creación.
4. Validar suma de pesos: `(suma_actual - accion.Peso) + request.Peso <= 1.0`.
5. Si cambian las fechas y el `% progreso > 0`, recalcular status (RN-017). Aunque la HU-020 trata el progreso, el status depende de la fecha actual.
6. Actualizar entidad y guardar.

### `EliminarAsync(id)`
1. Validar Tenant, obtener acción, validar Rol.
2. Validar restricciones: si tiene entregables asociados, lanzar error (o delegar al `ON DELETE CASCADE` según el DDL, pero mejor capturar `DbException` FK). Nota: El DDL de `entregable_adjunto` dice `ON DELETE CASCADE`, por lo que se eliminan automáticamente.
3. Eliminar acción.

## Queries DAL (`AccionPlanRepository`)
- `InsertAsync`: SQL paramétrico usando `RETURNING *` y `INSERT INTO accion_plan ...`.
- `UpdateAsync`: `UPDATE accion_plan SET ... WHERE id = @Id AND tenant_id = @TenantId`.
- `DeleteAsync`: `DELETE FROM accion_plan WHERE id = @Id AND tenant_id = @TenantId`.
- `ObtenerPorIdAsync`: JOIN con `usuario` para obtener el `ResponsableNombre`.
- `ListarPorObjetivoCgAsync`: Listado ordenado por `orden ASC`.
- `ObtenerSumaPesosAsync(objetivoCgId)`: `SELECT COALESCE(SUM(peso), 0) FROM accion_plan WHERE objetivo_cg_id = @Id`.
- `ObtenerMaximoOrdenAsync(objetivoCgId)`: `SELECT COALESCE(MAX(orden), 0) FROM accion_plan WHERE objetivo_cg_id = @Id`.
### Utilidades
- `CicloFechaHelper.ObtenerRango(int añoFiscal, int mesInicio)`: Helper puro para calcular el rango de fechas válido. Devuelve `(DateOnly inicio, DateOnly fin)`.
