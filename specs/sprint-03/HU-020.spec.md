## Endpoints

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| `PATCH` | `/api/v1/acciones/{id:guid}/progreso` | `JefeArea` | Actualiza el % de progreso de una acción. Recalcula status y puntuación, guarda historial, recalcula progreso del CG. |
| `GET` | `/api/v1/acciones/{id:guid}/historial` | `JefeArea, Gerente` | Lista el historial de cambios de progreso de una acción. |

> **Nota de autorización:** `PATCH` solo `[Authorize(Policy = "RequireJefeAreaRole")]`. `GET historial` con `[Authorize(Roles = "JefeArea,Gerente")]` — el Gerente necesita ver el historial para su tablero (HU-016) y vistas consolidadas (HU-018). La BLL re-valida SEC-07 (verifica área) **únicamente para `PATCH`**. Para `GET historial` con rol Gerente, no aplica SEC-07 (lectura de solo lectura sin información sensible).

## Lógica BLL (paso a paso)

### `ActualizarProgresoAsync(Guid accionId, ActualizarProgresoRequest request, CancellationToken ct)`

1. **Validar TenantContext:** `TenantId` no nulo.
2. **Obtener la acción:** `IAccionPlanRepository.ObtenerPorIdAsync(accionId, tenantId)` → `NotFoundException` si no existe.
3. **Validar rol y área (SEC-07):** Si `Rol == "JefeArea"`, verificar `accion.AreaId == TenantContext.AreaId`. Lanza `AccesoDenegadoException` si no coincide.
4. **Capturar valores anteriores:** `progresoAnterior = accion.Progreso`, `statusAnterior = accion.Status`.
5. **Calcular nuevo Status (RN-017)** — 4 reglas de precedencia:
   - (1) Si `request.Progreso == 100` → `"Terminado"`
   - (2) Si `request.Progreso > 0` y `DateTime.UtcNow.Date <= accion.FechaVencimiento` → `"EnProgreso"`
   - (3) Si `request.Progreso == 0` y `DateTime.UtcNow.Date <= accion.FechaInicio` → `"NoIniciado"`
   - (4) Cualquier otro caso (`DateTime.UtcNow.Date > accion.FechaVencimiento` y `progreso < 100`) → `"Atrasado"`
6. **Calcular PuntuacionPonderada:** `puntuacionPonderada = accion.Peso * (request.Progreso / 100m)` (valor en rango 0–1).
7. **Actualizar la acción:** `accion.Progreso = request.Progreso`, `accion.Status = nuevoStatus`, `accion.PuntuacionPonderada = puntuacionPonderada`, `accion.UpdatedAt = DateTime.UtcNow`.
8. **Iniciar transacción explícita** (pasos 8–10 deben ser atómicos — si falla el recalc del CG, no queda inconsistencia):
   - 8a. **Persistir cambios en `accion_plan`:** `IAccionPlanRepository.UpdateAsync(accion, ct)`.
   - 8b. **Insertar historial** (solo si `progresoNuevo != progresoAnterior`): `IHistorialProgresoRepository.InsertAsync(new HistorialProgresoEntity { TenantId, AccionId, ProgresoAnterior, ProgresoNuevo, StatusAnterior, StatusNuevo, RegistradoPor = TenantContext.UserId }, ct)`.
   - 8c. **Recalcular progreso del CG (RN-018):** obtener nuevo progreso con `SELECT COALESCE(SUM(peso * progreso / 100.0), 0) FROM accion_plan WHERE objetivo_cg_id = @ObjetivoCgId AND tenant_id = @TenantId`.
   - 8d. **Recalcular semáforo del CG (F2):** obtener umbrales del tipo `PlanAccion` del ciclo activo → `SemaforoHelper.Evaluar(nuevoPorcentaje / 100m, umbral.Verde, umbral.Amarillo)` (el helper trabaja con valor 0–1).
   - 8e. **Actualizar `objetivo_cg`:** `IObjetivoCgRepository.RecalcularProgresoAsync(accion.ObjetivoCgId, nuevoPorcentaje, nuevoSemaforo, tenantId, ct)` — `UPDATE objetivo_cg SET progreso = @Progreso, semaforo = @Semaforo::semaforo_color, updated_at = NOW() WHERE id = @ObjetivoCgId AND tenant_id = @TenantId`.
   - 8f. **Commit** de la transacción.
9. **Comportamiento idempotente (F3):** Si `progresoNuevo == progresoAnterior` → omitir pasos 8a–8f (sin transacción, sin historial, sin recalc) y retornar `200 OK` con el estado actual. No lanzar error.
10. **Retornar `AccionPlanResponse`** con los datos actualizados.

### `ListarHistorialAsync(Guid accionId, CancellationToken ct)`

1. Validar TenantContext.
2. Validar que la acción exista y pertenezca al tenant.
3. Validar rol: Si `JefeArea`, verificar `accion.AreaId == TenantContext.AreaId` (SEC-07).
4. Devolver `IEnumerable<HistorialProgresoResponse>` ordenado por `created_at DESC`.

## Queries DAL

### `IHistorialProgresoRepository` (nuevo repositorio)

```csharp
Task InsertAsync(HistorialProgresoEntity entity, CancellationToken ct = default);
Task<IEnumerable<HistorialProgresoResponse>> ListarPorAccionAsync(Guid accionId, Guid tenantId, CancellationToken ct = default);
```

#### `InsertAsync`
```sql
INSERT INTO historial_progreso 
    (tenant_id, accion_id, progreso_anterior, progreso_nuevo, 
     status_anterior, status_nuevo, registrado_por)
VALUES 
    (@TenantId, @AccionId, @ProgresoAnterior, @ProgresoNuevo,
     @StatusAnterior::status_accion, @StatusNuevo::status_accion, @RegistradoPor)
RETURNING id, created_at;
```

#### `ListarPorAccionAsync`
```sql
SELECT hp.id                     AS Id,
       hp.accion_id              AS AccionId,
       hp.progreso_anterior      AS ProgresoAnterior,
       hp.progreso_nuevo         AS ProgresoNuevo,
       hp.status_anterior::text  AS StatusAnterior,
       hp.status_nuevo::text     AS StatusNuevo,
       hp.registrado_por         AS RegistradoPor,
       u.nombre                  AS RegistradoPorNombre,
       hp.created_at             AS CreatedAt
FROM historial_progreso hp
LEFT JOIN usuario u ON hp.registrado_por = u.id
WHERE hp.accion_id = @AccionId
  AND hp.tenant_id = @TenantId
ORDER BY hp.created_at DESC;
```

### `IObjetivoCgRepository` — método aditivo (firma actualizada)

```csharp
Task RecalcularProgresoAsync(Guid objetivoCgId, decimal nuevoPorcentaje, string nuevoSemaforo, Guid tenantId, CancellationToken ct = default);
```

```sql
UPDATE objetivo_cg
SET progreso   = @Progreso,
    semaforo   = @Semaforo::semaforo_color,
    updated_at = NOW()
WHERE id        = @ObjetivoCgId
  AND tenant_id = @TenantId;
```

> **Nota RLS (hallazgo crítico):** El subquery `SUM(peso * progreso / 100.0)` en `ActualizarProgresoAsync` paso 8c consulta `accion_plan` agregando **todas** las áreas del CG (RN-018 suma ponderada global). La política `accion_plan_policy` filtra por `area_id` para `JefeArea`. @BackendDev debe verificar que el connection string use `service_role` (BYPASSRLS) o que el subquery se ejecute con un rol de BD sin filtro `area_id`. Ver HANDOFF § Decisiones 2026-09-13.
