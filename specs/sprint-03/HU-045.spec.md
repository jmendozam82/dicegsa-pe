## Cimiento de frontend (aprobado — Flag 1 resuelto)

> Patrón de referencia: bloque "UI (vista Razor en PE-GOL.Aplicacion) — DIFERIDA" del spec HU-006 (L309-341), que define el patrón de vista Razor + ApiClient + navbar con logo/nombre de tenant. Este cimiento lo materializa y lo extiende con sesión/JWT.

### 1. `ApiClient` tipado con JWT — `PE-GOL.Aplicacion/Services/ApiClient.cs`

Cliente HTTP tipado que consume la API interna (04_ARQUITECTURA § 1: `Aplicacion → HTTP interno → API`). Registrado con `builder.Services.AddHttpClient<ApiClient>()` (IHttpClientFactory) en `Program.cs`.

| Miembro | Firma | Comportamiento |
|--------|-------|----------------|
| `GetAsync<T>(string path, IDictionary<string,string?>? query = null, CancellationToken ct = default)` | `Task<T>` | GET con query params opcionales. Desenvuelve `ApiResponse<T>.Data`. |
| `PostAsync<TReq,TRes>(string path, TReq body, CancellationToken ct = default)` | `Task<TRes>` | POST con body JSON. Desenvuelve `ApiResponse<TRes>.Data`. |
| `PutAsync<TReq,TRes>(string path, TReq body, CancellationToken ct = default)` | `Task<TRes>` | PUT con body JSON. |
| `PostAsync<TRes>(string path, CancellationToken ct = default)` | `Task<TRes>` | POST sin body (activar/desactivar). |

Reglas de comportamiento:
1. **Base URL** desde configuración `Api:BaseUrl` (appsettings de `PE-GOL.Aplicacion`; apunta a la API interna). Nunca hardcodeada.
2. **Bearer token**: adjunta `Authorization: Bearer {accessToken}` desde la sesión (vía `SesionService`) en cada request. Si no hay token → `UnauthorizedException` (el controlador redirige a login).
3. **Desenvolvimiento del wrapper** (ARCH-07): si `ApiResponse<T>.Success == true` → retorna `Data`. Si `Success == false` → lanza `ApiClientException` con `StatusCode` y `Errors` (lista de mensajes del servidor) — el controlador los muestra (CA #5).
4. **Flujo de refresh en 401** (SEC-01): si la respuesta es 401 → `POST /api/v1/auth/refresh` con el refresh token almacenado (rotación D1 de HU-004) → actualiza tokens en sesión → **reintenta el request original una sola vez**. Si el refresh falla (401) → limpia sesión → lanza `UnauthorizedException` → el controlador redirige a `/Auth/Login`.
5. **Manejo de códigos**: 400/422 → `ApiClientException` con `Errors` (validación de forma/negocio); 403 → `ApiClientException` con mensaje de rol; 404 → `ApiClientException` con mensaje de no encontrado; 500 → `ApiClientException` genérico "Error interno del servidor" (sin filtrar detalles).
6. **SEC-05**: nunca se construyen URLs concatenando input del usuario; los query params se codifican con `Uri.EscapeDataString` o `QueryHelpers.AddQueryString`.

### 2. Sesión y autenticación MVC — `PE-GOL.Aplicacion/Services/SesionService.cs` + `Controllers/AuthController.cs`

**Sesión** (cookie de sesión ASP.NET Core, sin librería externa):
- `SesionService` (scoped, usa `IHttpContextAccessor` + `ISession`): guarda/lee `AccessToken`, `RefreshToken`, `UsuarioJson` (serialización de `UsuarioResponse` de HU-003/HU-004: `id`, `nombre`, `correo`, `rol`, `tenantId`, `areaId`).
- `CerrarSesion()`: limpia las claves de sesión.

**Autenticación MVC** (cookie auth de ASP.NET Core — `AddAuthentication(CookieAuthenticationDefaults.AuthenticationScheme)` + `AddCookie()`):
- Al hacer login exitoso, se emite el **cookie de autenticación MVC** con claims derivados del `UsuarioResponse` del JWT: `ClaimTypes.NameIdentifier = usuario.id`, `ClaimTypes.Role = usuario.rol`, `ClaimTypes.Name = usuario.nombre`. El **JWT se guarda en sesión** (no en el cookie) y lo usa el `ApiClient`.
- `[Authorize(Roles = "SuperAdmin")]` en `TenantController` (MVC) → el rol se valida en la capa MVC **y** la API re-valida el JWT (doble capa, consistente con ARCH-04).
- `[AllowAnonymous]` en `AuthController` (login/refresh/logout).

**`AuthController` (MVC)** — flujo mínimo viable (Flag 2 resuelto):

| Método | Ruta | Descripción |
|--------|------|-------------|
| GET | `/Auth/Login` | Renderiza `Views/Auth/Login.cshtml` (AllowAnonymous). |
| POST | `/Auth/Login` | Envía `POST /api/v1/auth/login` con `LoginRequest`. Éxito → guarda tokens en sesión + emite cookie MVC con claims → si `requiereCambioPwd` → redirect `/Auth/CambiarContrasena`; si no → redirect a `returnUrl` o `/Tenants`. 401 → re-render con error "Credenciales inválidas" (mensaje del servidor). |
| POST | `/Auth/Logout` | Envía `POST /api/v1/auth/logout` (best-effort, idempotente D10 HU-004) → `SesionService.CerrarSesion()` + `HttpContext.SignOutAsync()` → redirect `/Auth/Login`. |
| GET/POST | `/Auth/CambiarContrasena` | Envía `POST /api/v1/auth/cambiar-contrasena` con `CambiarContrasenaRequest` (usuarioId del JWT, SEC-06). Éxito → limpia flag `requiereCambioPwd` → redirect `/Tenants`. 422 → re-render con errores. |

> **Nota seed:** el SuperAdmin seed (`superadmin@pegol.app`) tiene `requiere_cambio_pwd=TRUE` (06 L592-598) → el flujo de cambio de contraseña en primer login es **obligatorio** para que el SA llegue a la pantalla de tenants (parte del cimiento).

## Lógica del controlador MVC (paso a paso)

> No hay cambios en BLL ni DAL (backend HU-001/HU-002/HU-004 completo). La lógica nueva vive en la capa Aplicacion: `TenantController` (MVC), `AuthController` (MVC), `ApiClient`, `SesionService`.

### `TenantController` — `PE-GOL.Aplicacion/Controllers/TenantController.cs`

Clase con `[Authorize(Roles = "SuperAdmin")]` (Flag 3 resuelto). Ctor: `(IApiClient apiClient, ILogger<TenantController> logger)`.

**1. `Index(int page = 1, int pageSize = 10, string? estado = null, Guid? planId = null)` — GET `/Tenants`**
1. Cargar catálogo de planes: `apiClient.GetAsync<List<PlanResponse>>("/api/v1/planes")`. Si falla → log warning + catálogo vacío (el select de filtro muestra solo "Todos los planes"; el listado sigue funcionando).
2. Sanear `page` (≥ 1) y `pageSize` (1..100; default 10).
3. Construir query params: `page`, `pageSize`, `estado` (si no vacío), `planId` (si tiene valor).
4. `resultado = apiClient.GetAsync<PagedResult<TenantResponse>>("/api/v1/tenants", query)`.
5. Construir `TenantsIndexViewModel { Items, Page, PageSize, Total, TotalPages, EstadoFiltro, PlanIdFiltro, Planes }`.
6. Retornar `View(model)`. Si `Items.Count == 0` → la vista renderiza `.empty-state` (UX-05).
7. Excepciones: `UnauthorizedException` → redirect `/Auth/Login` · `ApiClientException` → `TempData["Error"]` + re-render con modelo vacío (o página de error si 500).

**2. `Create()` — GET `/Tenants/Create`**
1. Cargar catálogo de planes (mismo paso 1 de Index).
2. Retornar `View(new TenantFormViewModel { Planes = planes })`.

**3. `Create(TenantCreateRequest request)` — POST `/Tenants/Create`**
1. (jQuery Validate ya validó forma en cliente; el servidor MVC re-valida con `ModelState` como capa extra).
2. `apiClient.PostAsync<TenantCreateRequest, TenantResponse>("/api/v1/tenants", request)`.
3. Éxito (201) → `TempData["Success"] = "Tenant '{nombre}' creado correctamente."` → `RedirectToAction(nameof(Index))`.
4. `ApiClientException` 400/422 → recargar planes → re-render `View` con `ModelState.AddModelError` por cada `Errors` del servidor (CA #5).
5. `UnauthorizedException` → redirect `/Auth/Login`.

**4. `Edit(Guid id)` — GET `/Tenants/Edit/{id}`**
1. `tenant = apiClient.GetAsync<TenantResponse>($"/api/v1/tenants/{id}")`.
2. Cargar planes (para el select).
3. Retornar `View(TenantFormViewModel)` precargado con los valores del tenant.
4. `ApiClientException` 404 → `NotFound()` (página 404 estándar).

**5. `Edit(Guid id, TenantUpdateRequest request)` — POST `/Tenants/Edit/{id}`**
1. `apiClient.PutAsync<TenantUpdateRequest, TenantResponse>($"/api/v1/tenants/{id}", request)`.
2. Éxito (200) → `TempData["Success"]` → redirect `Index`.
3. 400/422 → recargar planes → re-render con errores del servidor.
4. 404 → `NotFound()`.

**6. `Activar(Guid id)` — POST `/Tenants/Activar/{id}`** (form del modal de confirmación)
1. `apiClient.PostAsync<TenantResponse>($"/api/v1/tenants/{id}/activar")`.
2. Éxito → `TempData["Success"] = "Tenant activado."` → redirect `Index`.
3. 422 (ya activo) → `TempData["Error"]` con el mensaje del servidor → redirect `Index`.

**7. `Desactivar(Guid id)` — POST `/Tenants/Desactivar/{id}`**
1. `apiClient.PostAsync<TenantResponse>($"/api/v1/tenants/{id}/desactivar")`.
2. Éxito → `TempData["Success"] = "Tenant desactivado. Sus usuarios no podrán iniciar sesión."` → redirect `Index`.
3. 422 (ya inactivo) → `TempData["Error"]` → redirect `Index`.

### `AuthController` (MVC) — cimiento (paso a paso resumido)

**`Login(LoginRequest request)` POST:**
1. `respuesta = apiClient.PostAsync<LoginRequest, LoginResponse>("/api/v1/auth/login", request)` (sin Bearer — AllowAnonymous).
2. `SesionService.GuardarSesion(respuesta.AccessToken, respuesta.RefreshToken, respuesta.Usuario)`.
3. Emitir cookie MVC: `SignInAsync` con claims (`NameIdentifier`, `Role = usuario.Rol`, `Name = usuario.Nombre`).
4. Si `respuesta.RequiereCambioPwd` → redirect `/Auth/CambiarContrasena`; si no → redirect `returnUrl ?? "/Tenants"`.
5. 401 → re-render `Login` con error del servidor ("Credenciales inválidas", "Cuenta bloqueada...", "Tenant desactivado..." — mensajes de HU-004).

**`Logout()` POST:** `POST /api/v1/auth/logout` (best-effort) → `CerrarSesion()` + `SignOutAsync()` → redirect `/Auth/Login`.

**`CambiarContrasena(CambiarContrasenaRequest request)` POST:** `POST /api/v1/auth/cambiar-contrasena` → éxito → limpiar flag `requiereCambioPwd` → redirect `/Tenants` · 422 → re-render con errores.
