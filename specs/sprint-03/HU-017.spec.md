# Spec HU-017 — CRUD de Objetivos CG
**Sprint:** 3 · **Épica:** EP-06 · **Pts:** 5 · **Estado:** Implementado

## Contexto
HU-017: Como Jefe de Área (JEF), quiero crear, editar y eliminar Objetivos CG de mi área con código, descripción, pilar asociado y trimestre objetivo, para registrar formalmente los compromisos estratégicos de mi área para el ciclo.

## Verificación DDL y Modelo de Datos
La especificación se alinea estrictamente con `06_MODELO_DATOS.md` (L215-231):
- `tenant_id`, `ciclo_id`, `area_id`, `pilar_id` (UUIDs).
- `progreso` es **`DECIMAL(5,4)`** (rango 0.0000 a 1.0000, no INT).
- `semaforo` es el **enum PostgreSQL `semaforo_color`** (`'Verde'`, `'Amarillo'`, `'Rojo'`). Por defecto `'Rojo'`.
- `trimestre_objetivo` es el **enum PostgreSQL `trimestre`** (`'Q1'`, `'Q2'`, `'Q3'`, `'Q4'`).
- `UNIQUE (ciclo_id, codigo)` existe y prevendrá duplicados exactos en BD.
- Índice `idx_objetivo_cg_area` optimiza las búsquedas por área.
- Columna `orden` de tipo `INT` confirmada en DDL para uso en queries `ORDER BY`.
- RLS `objetivo_cg_policy` habilitado.

## Flags y Decisiones Críticas (Aprobadas por Jorge)
- **[F1] Permisos de Escritura:** Exclusivo para `JefeArea` según CA y RN-007. El Gerente tiene acceso de lectura y GET.
- **[F2] Regla RC-12 (Ciclo Cerrado):** Confirmado el bloqueo defensivo en la BLL si el ciclo activo está cerrado.
- **[F3] DELETE Físico:** Confirmado DELETE físico con validación previa de integridad contra `accion_plan` (evita Foreign Key Constraint error 23503).
- **[F4] Semáforo Inicial:** Confirmado insertar `'Rojo'` directamente ya que el progreso inicial es `0.0000`.
- **[F5] Repositorio (Punto de Inflexión Arquitectónica):** Confirmada la creación de `IObjetivoCgRepository`. Las entidades de negocio con CRUD completo independiente tendrán repositorios propios en vez de usar `CicloRepository` para evitar un God Object. Documentado en `HANDOFF_PE_GOL.md`.

## Endpoints

| Método | Ruta | Auth | Descripción |
|---|---|---|---|
| GET | `/api/v1/objetivos-cg` | `JefeArea` | Lista los Objetivos CG del área del JEF en el ciclo activo, incluyendo progreso y semáforo. |
| GET | `/api/v1/objetivos-cg/{id}` | `JefeArea` | Obtiene el detalle de un Objetivo CG específico. |
| POST | `/api/v1/objetivos-cg` | `JefeArea` | Crea un nuevo Objetivo CG. Código autogenerado (`GOLn.CGm`). |
| PUT | `/api/v1/objetivos-cg/{id}` | `JefeArea` | Edita `descripcion`, `pilar_id` o `trimestre_objetivo`. |
| DELETE | `/api/v1/objetivos-cg/{id}` | `JefeArea` | Elimina un Objetivo CG físicamente si no tiene acciones en plan. |

> **Nota SEC-06:** `tenant_id` y `area_id` provienen estrictamente del `TenantContext` inyectado por JWT. `ciclo_id` proviene de `ObtenerCicloActivoAsync` de la BLL.

## Lógica BLL (paso a paso)

### 1. Crear (`CrearAsync`)
1. Validar request con FluentValidation.
2. Validar Rol == `JefeArea`. Validar TenantContext.
3. Obtener ciclo activo. Si no hay, `NotFoundException`.
4. Si el ciclo está "Cerrado" (RC-12), `ValidacionExcepcion("Ciclo cerrado")`.
5. Validar que el `PilarId` existe y pertenece al mismo `tenant_id` y `ciclo_id`.
6. **Autogeneración del Código (Carrera TOCTOU):**
   - Obtener el `codigo` del Área (ej: "GOL1").
   - Hacer un `COUNT(1)` de `objetivo_cg` para esta área en el ciclo activo.
   - Código será `{area_codigo}.CG{count + 1}`.
   - *Mitigación TOCTOU:* Se confía en la restricción `UNIQUE (ciclo_id, codigo)` de la base de datos. Si hay una inserción concurrente que choca, Dapper lanzará `PostgresException` (23505), la BLL lo atrapará y lanzará `ValidacionExcepcion("Conflicto generando código, intente de nuevo")`.
7. Insertar en DAL (`progreso = 0`, `semaforo = 'Rojo'`).
8. Registrar en el Log de Auditoría (ADR-003): `accion` = "CREATE", `entidad` = "ObjetivoCg", `valor_nuevo` con los datos creados.

### 2. Editar (`ActualizarAsync`)
1. Validar request con FluentValidation. Rol == `JefeArea`.
2. Obtener ciclo activo. Verificar estado (bloquear si Cerrado).
3. Obtener el CG por ID asegurando que pertenece al `tenant_id` y al `area_id` del Jefe. Si no, `NotFoundException`.
4. Validar que el nuevo `PilarId` existe y corresponde al ciclo/tenant.
5. Actualizar los campos y `updated_at = NOW()`.
6. Registrar Auditoría: `accion` = "UPDATE", `valor_anterior` y `valor_nuevo`.

### 3. Eliminar (`EliminarAsync`)
1. Validar Rol. Obtener ciclo activo y verificar estado.
2. Obtener el CG verificando pertenencia al `tenant_id` y `area_id`. Si no, `NotFoundException`.
3. Consultar a DAL si existe algún registro en `accion_plan` con `objetivo_cg_id = {Id}`.
4. Si existe, lanzar `ValidacionExcepcion("No se puede eliminar el objetivo estratégico porque tiene acciones asociadas")`.
5. Ejecutar DELETE físico en DAL.
6. Registrar Auditoría: `accion` = "DELETE", `valor_anterior` con los datos eliminados.

### 4. Listar (`ListarAsync`)
1. Obtener ciclo activo. Retornar `IEnumerable<ObjetivoCgResponse>` filtrando por `tenant_id` y `area_id` del Jefe, incluyendo `JOIN pilar` para obtener el `PilarNombre`.

## Queries DAL

```sql
-- Verificar FK con Accion Plan
SELECT EXISTS(SELECT 1 FROM accion_plan WHERE objetivo_cg_id = @Id AND tenant_id = @TenantId);

-- Conteo para autogenerado
SELECT COUNT(1) FROM objetivo_cg WHERE tenant_id = @TenantId AND ciclo_id = @CicloId AND area_id = @AreaId;

-- Obtener Area Codigo
SELECT codigo FROM area WHERE id = @AreaId AND tenant_id = @TenantId;

-- Lista completa con PilarNombre
SELECT o.id, o.pilar_id, p.nombre AS pilar_nombre, o.codigo, o.descripcion, o.trimestre_objetivo::text, o.progreso, o.semaforo::text, o.created_at, o.updated_at
FROM objetivo_cg o
INNER JOIN pilar p ON o.pilar_id = p.id
WHERE o.tenant_id = @TenantId AND o.ciclo_id = @CicloId AND o.area_id = @AreaId
ORDER BY o.orden ASC, o.created_at ASC;

-- Insertar (Dapper maneja enums PostgreSQL haciendo cast)
INSERT INTO objetivo_cg (tenant_id, ciclo_id, area_id, pilar_id, codigo, descripcion, trimestre_objetivo, progreso, semaforo)
VALUES (@TenantId, @CicloId, @AreaId, @PilarId, @Codigo, @Descripcion, @TrimestreObjetivo::trimestre, 0.0000, 'Rojo'::semaforo_color)
RETURNING id;
```

## Validaciones FluentValidation
- `Descripcion`: `NotEmpty`, `MaximumLength(500)`.
- `PilarId`: `NotEmpty`.
- `TrimestreObjetivo`: `NotEmpty`, `Must(t => new[] { "Q1", "Q2", "Q3", "Q4" }.Contains(t))`.
