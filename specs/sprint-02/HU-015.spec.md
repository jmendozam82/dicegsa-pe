**Sprint:** 2 · **Épica:** EP-05 · **Pts:** 5 · **Estado:** Implementado

## Contexto

Backlog `03_BACKLOG.md` L305-317: *"Como Jefe de Área quiero ver al ingresar un tablero resumen de mi área con el estado actual de OKRs, acciones y presupuesto"*.

**Criterios de Aceptación (CA):**
1. Tarjetas con: Total OKRs · OKRs alcanzados · % avance plan de acción · acciones atrasadas · días al vencimiento más cercano.
2. Semáforo global del área (promedio de OKRs y plan de acción).
3. Acceso directo desde el tablero a: mis Objetivos CG, Plan de Acción, OKRs, CAPEX, OPEX.
4. El tablero solo muestra datos del ciclo activo.

**Reglas de dominio aplicables:** RN-007 (JEF solo lectura) · RN-017 (status de acciones) · RN-038/039 (semáforo) · RC-01 (máximo 1 ciclo `Activo` por tenant) · SEC-06 (tenant_id/area_id/ciclo_id nunca del cliente) · SEC-07 (JEF solo su `area_id`) · DB-04 (campos calculados en BLL, nunca en SQL).

**Alcance (decisión D-A):** 100% backend, patrón del Sprint 2 (HU-005, HU-009..HU-014). El entregable es el **endpoint de agregación de solo lectura + contrato de datos estable**. La vista Razor se difiere al cimiento de frontend (HU-045+, Sprint 3) y usará los componentes `.kpi-card` del Design System § 6.1.

**Límite de alcance (decisión D-M):** HU-038 (Sprint 8) es el *Dashboard visual* con gráficas (RF-060). HU-015 es el *tablero resumen* (tarjetas del CA #1). No se implementan gráficas ni métricas adicionales de RF-058 en esta HU.

## Lógica BLL (paso a paso)

Servicio nuevo: `PE-GOL.BLL/Services/DashboardService.cs` + `IDashboardService` (completa `04_ARQUITECTURA.md` L134/L146, decisión D-J). Método: `Task<ApiResponse<TableroJefeAreaResponse>> ObtenerTableroJefeAreaAsync(CancellationToken ct)`.

1. **D12 — Rol:** `_tenantContext.Rol != "JefeArea"` → `AccesoDenegadoException` (403). Solo el JEF tiene tablero en esta HU (decisión D-F; HU-016 es del GER).
2. **Tenant:** `tenantId = ObtenerTenantIdOThrow()` → null → `NotFoundException` (404).
3. **CA #4 — Ciclo activo:** `ciclo = _repository.ObtenerCicloActivoAsync(tenantId, ct)` (DAL-D1) → null → `NotFoundException` "No hay un ciclo activo para el tenant" (404). RC-01 garantiza máximo 1 fila.
4. **SEC-07 — Área del JEF:** `areaId = _tenantContext.AreaId` → null → `NotFoundException` "El usuario no tiene un área asignada" (404).
5. **Validar área:** `area = _repository.ObtenerAreaPorIdAsync(tenantId, ciclo.Id, areaId, ct)` (DAL-A2 reutilizada) → null → `NotFoundException` (404).
6. **Umbrales:** `umbrales = _repository.ObtenerUmbralesAsync(tenantId, ciclo.Id, ct)` (DAL-C10 reutilizada) → mapear por `Tipo`: `umbralKpi` (tipo `"KPI"`) y `umbralPlanAccion` (tipo `"PlanAccion"`). Si falta un tipo → defaults `0.90`/`0.70` (patrón HU-008 D5, constantes `UmbralVerdeDefault`/`UmbralAmarilloDefault` de `CicloService`).
7. **OKRs:** `resumenOkrs = _repository.ObtenerResumenOkrsAreaAsync(tenantId, ciclo.Id, areaId, ct)` (DAL-D3). Lee `puntuacion_final`/`semaforo` **persistidos** (mantenidos por la BLL de HU-024+, DB-04; decisión D-C).
8. **Plan de Acción:** `resumenPlan = _repository.ObtenerResumenPlanAccionAreaAsync(tenantId, ciclo.Id, areaId, ct)` (DAL-D4). Lee `progreso` persistido de `objetivo_cg` (HU-017+).
9. **Acciones (recalculo en BLL, decisión D-D):** `acciones = _repository.ListarAccionesAreaAsync(tenantId, ciclo.Id, areaId, ct)` (DAL-D5). En BLL:
   - `accionesAtrasadas = acciones.Count(a => EsAccionAtrasada(a))` con `EsAccionAtrasada = DateTime.Today > a.FechaVencimiento.Date && a.Progreso < 100` (RN-017 regla 4). No se lee el `status` persistido (puede estar desactualizado vs. el batch nocturno RN-040).
   - `pendientes = acciones.Where(a => a.Progreso < 100)` → `diasAlVencimiento`:
     - Sin pendientes → `null`.
     - Con pendientes futuras (`FechaVencimiento.Date >= DateTime.Today`): mínimo sobre las **pendientes futuras** (`pendientesFuturas.Min(a => (a.FechaVencimiento.Date - DateTime.Today).Days)`).
     - Si **todas** las pendientes están vencidas (`FechaVencimiento.Date < DateTime.Today`): máximo de fecha de vencimiento (la más reciente) expresado como días negativos (`pendientes.Max(a => (a.FechaVencimiento.Date - DateTime.Today).Days)` — valor negativo = vencida hace N días).
     - **Semántica fijada por los tests 10/11/12/17 de @QA y confirmada por Jorge (2026-09-20):** *"mínimo sobre pendientes futuras; si todas vencidas, máximo fecha de vencimiento (más reciente) expresado como días negativos; null si sin pendientes"*. La fórmula literal del spec original (`min` sobre todas las pendientes) quedó reemplazada.
10. **Semáforos (BLL, DB-04; decisión D-E):**
    - `semaforoOkrs = SemaforoHelper.Evaluar(resumenOkrs.PromedioPuntuacionOkrs, umbralKpi.UmbralVerde, umbralKpi.UmbralAmarillo)`.
    - `semaforoPlan = SemaforoHelper.Evaluar(resumenPlan.AvancePlanAccion, umbralPlanAccion.UmbralVerde, umbralPlanAccion.UmbralAmarillo)`.
    - `promedioGlobal = (resumenOkrs.PromedioPuntuacionOkrs + resumenPlan.AvancePlanAccion) / 2`.
    - `semaforoGlobal = SemaforoHelper.Evaluar(promedioGlobal, umbralKpi.UmbralVerde, umbralKpi.UmbralAmarillo)`.
11. **Mapear y responder:** construir `TableroJefeAreaResponse` → 200 `ApiResponse<TableroJefeAreaResponse>`.

**SemaforoHelper** (nuevo, `PE-GOL.Utility/Helpers/SemaforoHelper.cs` — completa `04_ARQUITECTURA.md` L173; decisión D-I):

```csharp
public static class SemaforoHelper
{
    /// <summary>Evalúa un valor 0..1 contra los umbrales del ciclo (05_DOMINIO.md L158-161).</summary>
    public static string Evaluar(decimal valor, decimal umbralVerde, decimal umbralAmarillo)
    {
        if (valor >= umbralVerde) return "Verde";
        if (valor >= umbralAmarillo) return "Amarillo";
        return "Rojo";
    }
}
```

**Sin auditoría** (solo lectura — patrón HU-005 CA #3; decisión D-H). **Sin transacción** (solo lecturas).

## Queries DAL

Extensiones de `PE-GOL.DAL/Interfaces/ICicloRepository.cs` (decisión D-K: las entidades del tablero son hijas del agregado Ciclo — patrón D-I de HU-009/013; no se crea `DashboardRepository`). Todas con `WHERE tenant_id = @TenantId` primero y `AND area_id = @AreaId` (SEC-07).

| ID | Método | SQL parametrizado |
|----|--------|-------------------|
| **DAL-D1** | `ObtenerCicloActivoAsync(Guid tenantId, CancellationToken ct)` → `CicloEntity?` | `SELECT id, tenant_id, nombre, año_fiscal, mes_inicio, estado, created_by, activated_at, closed_at, created_at, updated_at FROM ciclo WHERE tenant_id = @TenantId AND estado = 'Activo' LIMIT 1;` |
| **DAL-D3** | `ObtenerResumenOkrsAreaAsync(Guid tenantId, Guid cicloId, Guid areaId, CancellationToken ct)` → `ResumenOkrsAreaDto` | `SELECT COUNT(o.id) AS total_okrs, COUNT(o.id) FILTER (WHERE o.semaforo = 'Verde') AS okrs_alcanzados, COALESCE(AVG(o.puntuacion_final), 0) AS promedio_puntuacion_okrs FROM okr o WHERE o.tenant_id = @TenantId AND o.ciclo_id = @CicloId AND o.area_id = @AreaId;` |
| **DAL-D4** | `ObtenerResumenPlanAccionAreaAsync(Guid tenantId, Guid cicloId, Guid areaId, CancellationToken ct)` → `ResumenPlanAccionAreaDto` | `SELECT COALESCE(AVG(ocg.progreso), 0) AS avance_plan_accion FROM objetivo_cg ocg WHERE ocg.tenant_id = @TenantId AND ocg.ciclo_id = @CicloId AND ocg.area_id = @AreaId;` |
| **DAL-D5** | `ListarAccionesAreaAsync(Guid tenantId, Guid cicloId, Guid areaId, CancellationToken ct)` → `IEnumerable<AccionTableroDto>` | `SELECT id, progreso, fecha_inicio, fecha_vencimiento FROM accion_plan WHERE tenant_id = @TenantId AND ciclo_id = @CicloId AND area_id = @AreaId;` |
| Reuso | `ObtenerAreaPorIdAsync(Guid tenantId, Guid cicloId, Guid areaId, CancellationToken ct)` → `AreaEntity?` | DAL-A2 existente (HU-009) |
| Reuso | `ObtenerUmbralesAsync(Guid tenantId, Guid cicloId, CancellationToken ct)` → `IEnumerable<UmbralSemaforoEntity>` | DAL-C10 existente (HU-008) |

> Nota: `COUNT`/`AVG`/`FILTER` son agregaciones de lectura (patrón DAL-P1 de HU-013); el **semáforo** (Verde/Amarillo/Rojo) y el **status** de acciones se calculan en BLL (DB-04), nunca en SQL.

## Resolución de flags — Jorge (2026-09-20)

- **F1 — Alcance backend-only:** CONFIRMADO. Entregable = endpoint de agregación + contrato de datos estable; vista Razor diferida a HU-045+ (Sprint 3). Consistente con las 7 HUs previas del Sprint 2.
- **F2 — Semáforo global:** promedio numérico `(promedio_puntuacion_okrs + avance_plan_accion) / 2` evaluado contra **umbrales KPI**. Razón de Jorge: el promedio discreto de semáforos tiene problema de semántica ("¿promedio de Verde y Rojo?"); el promedio numérico es más informativo y coherente con los semáforos individuales. Umbrales KPI como referencia uniforme para v1.0; si se quiere ponderar distinto en el futuro, es cambio de BLL sin romper el contrato del DTO.
- **F3 — Rol:** CONFIRMADO solo `JefeArea` en HU-015. El tablero del GER es HU-016 (Sprint 3). El `DashboardController` puede albergar ambos endpoints sin romper contratos.
- **F4 — Atrasadas recalculadas en BLL:** CONFIRMADO. El `status` persistido depende del batch nocturno (RN-040) y puede estar desactualizado; la lógica `fecha_vencimiento < hoy && progreso < 100` con fecha del servidor es precisa y reproducible.
- **F5 — Datos vacíos → "Rojo":** CONFIRMADO con fórmula pura (0 < umbral amarillo → Rojo). Sin estado especial "Sin datos" en el DTO; la vista futura (HU-045+) puede renderizar "Sin datos aún" cuando `TotalOkrs == 0` usando ese campo como señal.
- **F6 — Ruta standalone:** CONFIRMADO `GET /api/v1/dashboard/jefe-area`. El CA #4 dice "solo el ciclo activo" y la resolución del ciclo es responsabilidad del backend; el frontend no necesita conocer `cicloId` para acceder a su tablero.
- **F7 — Discrepancia backlog L316:** CONFIRMADO Sprint 2 según la tabla de planning (L900). @Documenter corrige el encabezado al cierre (patrón HU-011/012/013/014).
- **F8 — TenantContext sin CicloId:** CONFIRMADO no corregir en esta HU. DAL-D1 resuelve el ciclo activo (lectura barata con índice, `estado = 'Activo' LIMIT 1`). Si en el futuro múltiples endpoints necesitan el ciclo activo, se evalúa añadir `CicloId?` al TenantContext con ADR separado.
