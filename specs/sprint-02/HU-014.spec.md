## Contexto

Backlog `03_BACKLOG.md` L282-293 (EP-04, L262-264): **Como GER** quiero asociar a cada pilar los objetivos esperados por trimestre (Q1–Q4) como texto de referencia, para comunicar a las áreas qué se espera de ellas en cada período del año.

**Criterios de Aceptación:**
1. Por cada pilar, campos de texto libre para Q1, Q2, Q3 y Q4.
2. Los trimestres son opcionales; no todos deben tener contenido.
3. Visible en modo lectura para Jefes de Área como guía al crear sus CGs.

## Endpoints

Anidados bajo `/api/v1/ciclos/{cicloId}/pilares`, en `PE-GOL.API/Controllers/CicloController.cs` (mismo controller de HU-007..HU-013: los pilares son **hijos del agregado Ciclo** — D-J). `{cicloId}` y `{pilarId}` son `:guid` en la ruta. **SEC-06:** `tenant_id` NUNCA viaja en body/query; se resuelve del JWT vía `TenantContext.TenantId`. **SEC-07 NO APLICA** (D-E, idéntico a HU-013): `pilar` es **corporativa** (sin columna `area_id`; RLS `pilar_policy` solo filtra por tenant) → el JefeArea lee **todos** los pilares del ciclo con sus objetivos trimestrales (RN-007: solo lectura), sin `AND area_id`. Respuestas siempre con `ApiResponse<T>` (ARCH-07).

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| GET | `/api/v1/ciclos/{cicloId}/pilares` | `[Authorize(Roles = "AdminTenant,Gerente,JefeArea")]` | **EXTENDIDO aditivamente (HU-013 → HU-014):** ahora incluye `ObjetivoQ1..Q4` (`string?`) en cada `PilarResponse` (CA #1, CA #3: JEF lee como guía). Mismo comportamiento de HU-013 (conteos CG/OKRs, `ORDER BY orden ASC, codigo ASC`). **No se crea endpoint GET nuevo** (D-B): el GET existente ya devuelve la fila completa; añadir los campos es backward-compatible. **404** si el ciclo no existe/pertenece a otro tenant o `TenantContext.TenantId` es null. |
| GET | `/api/v1/ciclos/{cicloId}/pilares/{pilarId}` | `[Authorize(Roles = "AdminTenant,Gerente,JefeArea")]` | **EXTENDIDO aditivamente:** detalle con `ObjetivoQ1..Q4` (CA #1, CA #3). **404** si el ciclo/pilar no existe o es de otro tenant. |
| PUT | `/api/v1/ciclos/{cicloId}/pilares/{pilarId}/objetivos-trimestrales` | `[Authorize(Roles = "Gerente")]` | **NUEVO (HU-014):** registra/edita los Objetivos de Área por Trimestre del pilar (CA #1, CA #2, RF-016, RN-006). Body: `ObjetivosTrimestralesUpdateRequest` (4 campos opcionales). Retorna 200 con `ApiResponse<PilarResponse>` (estado completo del pilar con los 4 campos). **403** rol ≠ GER (D12) · **404** ciclo/pilar inexistente o de otro tenant, o sin tenant · **422** si: ciclo `Cerrado` (RC-12), o algún objetivo >2000 chars (D-C). **El UPDATE solo toca `objetivo_q1..q4` + `updated_at`** — NO toca `codigo`/`nombre`/`estrategia_victoria`/`orden` (D-A, contrato HU-013 intacto). |

> **Nota de ruteo:** `objetivos-trimestrales` (segmento literal) no colisiona con `pilares/{pilarId:guid}` (constraint `:guid`), `filosofia`, `areas/{areaId:guid}` ni `responsables/{responsableId:guid}`.
> **No existe DELETE ni POST propios** (D-A): los objetivos trimestrales se gestionan como UPDATE sobre un pilar existente (el pilar se crea con HU-013; los 4 campos nacen null — CA #2). El ciclo `Cerrado` los congela (RC-12).

**Códigos HTTP posibles:** 200 (GET/PUT), 400 (body malformado), 401 (sin token), 403 (rol distinto — p. ej. ADM o JEF intentando PUT), 404 (ciclo/pilar inexistente o `TenantContext.TenantId` null), 422 (regla de negocio violada), 500 (error no controlado, `ExceptionMiddleware`).

### 3. `ActualizarObjetivosTrimestralesAsync(Guid cicloId, Guid pilarId, ObjetivosTrimestralesUpdateRequest request, CancellationToken ct)` — NUEVO (PUT)
1. **D12:** `_tenantContext.Rol != RolGerente` → `AccesoDenegadoException` (403). *(RN-006: el GER es el único con escritura del contenido estratégico — mismo criterio D-A de HU-011..HU-013.)*
2. `tenantId = ObtenerTenantIdOThrow()` → 404.
3. Ciclo existe: `_repository.ObtenerPorIdAsync(tenantId, cicloId, ct)` (DAL-C2 reutilizada) → null → 404.
4. **RC-12:** `ciclo.Estado == "Cerrado"` → `ValidacionException` (422) "Un ciclo Cerrado es de solo lectura". *(Borrador y Activo permitidos — D-F, mismo criterio de HU-011..HU-013.)*
5. `original = _repository.ObtenerPilarAsync(tenantId, cicloId, pilarId, ct)` (DAL-P3 **extendida**: SELECT incluye `objetivo_q1..q4`) → null → 404.
6. **Normalizar (trim + null, CA #2, D-H):** para cada trimestre `QX`:
   - `valor = request.ObjetivoQX?.Trim()`.
   - Si `string.IsNullOrWhiteSpace(valor)` → `null` (trimestre opcional sin contenido → se persiste null).
7. **Re-validación BLL (fuente de verdad, UX-04):**
   - Para cada trimestre no null: `valor.Length > MaxLongitudObjetivoTrimestral` → 422 "El objetivo del trimestre QX no puede exceder 2000 caracteres" (D-C).
8. **Snapshot de auditoría (ADR-003, D-I):** `valorAnterior = SnapshotObjetivosTrimestrales(original)` (solo los 4 campos del pilar previo).
9. **Transacción única** (`BeginTransactionAsync`, patrón HU-001..HU-013):
   - `_repository.ActualizarObjetivosTrimestralesAsync(new PilarObjetivosTrimestralesUpdateDto { TenantId, CicloId, PilarId, ObjetivoQ1 = q1, ObjetivoQ2 = q2, ObjetivoQ3 = q3, ObjetivoQ4 = q4 }, tx, ct)` (DAL-P10) → filas afectadas 0 → `InvalidOperationException`.
   - Auditoría: `_repository.InsertLogAsync(new LogAuditoriaInsert { TenantId, UsuarioId = _tenantContext.UserId, Accion = "UPDATE", Entidad = "Pilar", EntidadId = pilarId.ToString(), ValorAnterior = valorAnterior, ValorNuevo = SnapshotObjetivosTrimestrales(nuevo) }, tx, ct)` (DAL-C11 reutilizada, ADR-003, D-I).
   - `tx.Commit()`.
10. Re-lectura post-commit (DAL-P2 extendida) → 200 `ApiResponse<PilarResponse>` (con `ObjetivoQ1..Q4` poblados).
11. `catch (PostgresException ex) when (ex.SqlState == "23505")` → rollback explícito + 422 (residual defensivo: el UPDATE de DAL-P10 **no toca `codigo`** → el `UNIQUE (ciclo_id, codigo)` no puede violarse; se conserva el patrón por consistencia con el PUT de HU-013 L241). `catch` general → rollback + rethrow.

> **No se toca `SnapshotPilar` de HU-013** (D-I): los CREATE/UPDATE/DELETE de HU-013 siguen auditando `{"codigo","nombre","estrategia_victoria","orden"}`; HU-014 audita **solo su alcance** (`{"objetivo_q1".."objetivo_q4"}`) — mismo criterio D-K de HU-013 y D-D de HU-012 (auditar solo lo que gestiona cada operación).
> **No se toca `CicloService.ActivarAsync`** (HU-007/HU-011): la activación no exige objetivos trimestrales (CA #2: son opcionales). No se reabre un spec cerrado.
