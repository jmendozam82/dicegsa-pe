## Contexto

Backlog `03_BACKLOG.md` L185-199: **Como ADM** quiero registrar, editar y desactivar las Áreas Estratégicas del ciclo para estructurar las unidades operativas que participan en el plan.

**Criterios de Aceptación:**
1. Crear área con: código GOL (auto-generado secuencial), nombre, comentarios opcionales.
2. Asignar un Jefe de Área responsable del catálogo de responsables.
3. Validar que un responsable no esté asignado a más de un área en el mismo ciclo (RN-012).
4. Límite de áreas según plan de suscripción del tenant (RN-010).
5. Al desactivar un área, sus datos permanecen en solo lectura.

**Nota backlog L197:** la clonación de áreas del CA #5 de HU-007 se completa en esta HU (contrato `ClonarAsync` de HU-007 queda abierto para extenderlo).

**Reglas de dominio aplicables** (`02_REQUERIMIENTOS.md`):
- **RN-010** (L281): 1..20 áreas activas por ciclo, configurable por plan.
- **RN-011** (L282): cada área debe tener **exactamente un responsable (Jefe de Área)**; no puede quedar un área sin responsable en estado Activo.
- **RN-012** (L283): un responsable puede ser asignado a **una sola área por ciclo**.
- **RN-007** (L271): JefeArea tiene **solo lectura** a la configuración del ciclo (las áreas son parte de esa configuración).
- **RC-12/RN-004**: ciclo `Cerrado` = solo lectura (patrón HU-007/HU-008).

**Modelo de datos** (`06_MODELO_DATOS.md` L194-212):
```sql
CREATE TABLE area (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID         NOT NULL REFERENCES tenant(id),
    ciclo_id        UUID         NOT NULL REFERENCES ciclo(id),
    codigo          VARCHAR(10)  NOT NULL,
    nombre          VARCHAR(150) NOT NULL,
    comentarios     TEXT,
    responsable_id  UUID         REFERENCES usuario(id),
    orden           INT          NOT NULL DEFAULT 0,
    activa          BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    UNIQUE (ciclo_id, codigo)
);
CREATE INDEX idx_area_ciclo ON area(ciclo_id);
-- FK circular usuario → area (L211-212): usuario.area_id REFERENCES area(id)
```
- RLS `area_tenant_policy` (L511-518): `tenant_id = auth.tenant_id() AND (rol IN ('SuperAdmin','AdminTenant','Gerente') OR id = auth.area_id())` — el JefeArea solo ve **su** área.
- `accion_auditoria` (L46) incluye `DEACTIVATE` → la desactivación se audita con esa acción (no DELETE).
- **El DDL NO tiene índice único para RN-012** → se requiere ADR-007 + migración `V004` (patrón ADR-006/V003). Ver § Flags #1.

**Alcance y puente con HU-010:** HU-010 (Sprint 3) gestionará el catálogo completo de responsables. En HU-009 el "catálogo de responsables" es el **puente pragmático**: usuarios del tenant con `rol = 'JefeArea'` y `estado = 'Activo'` (la FK `area.responsable_id → usuario(id)` del DDL lo confirma). El endpoint de candidatos (§ Endpoints) queda listo para que HU-010 lo reemplace/extienda sin romper contrato.

## Endpoints

Todos anidados bajo `/api/v1/ciclos/{cicloId}/areas`, en `PE-GOL.API/Controllers/CicloController.cs` (mismo controller de HU-007/HU-008: las áreas son **hijos del agregado Ciclo** — D2, mismo criterio que `umbral_semaforo`). `{cicloId}` y `{areaId}` son `:guid` en la ruta. **SEC-06:** `tenant_id` NUNCA viaja en body/query; se resuelve del JWT vía `TenantContext.TenantId`. **SEC-07:** a diferencia de `ciclo`/`umbral_semaforo`, `area` **SÍ es entidad de área** → el DAL aplica `AND id = @AreaId` cuando el rol es `JefeArea` (doble capa con la RLS `area_tenant_policy`). Respuestas siempre con `ApiResponse<T>` (ARCH-07).

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| GET | `/api/v1/ciclos/{cicloId}/areas` | `[Authorize(Roles = "AdminTenant,Gerente,JefeArea")]` | Listado de áreas del ciclo, `ORDER BY orden ASC`. Retorna `ApiResponse<List<AreaResponse>>`. **404** si el ciclo no existe/pertenece a otro tenant o `TenantContext.TenantId` es null. **JefeArea:** solo su área (SEC-07: `AND id = @AreaId`). |
| GET | `/api/v1/ciclos/{cicloId}/areas/{areaId}` | `[Authorize(Roles = "AdminTenant,Gerente,JefeArea")]` | Detalle de un área. Retorna `ApiResponse<AreaResponse>`. **404** si el ciclo/área no existe o es de otro tenant · **403** si rol `JefeArea` y `areaId != TenantContext.AreaId` (D12). |
| POST | `/api/v1/ciclos/{cicloId}/areas` | `[Authorize(Roles = "AdminTenant")]` | Crea un área con **código GOL auto-generado** (CA #1). Body: `AreaCreateRequest`. Retorna **201** con `ApiResponse<AreaResponse>`. **403** rol ≠ ADM (D12) · **404** ciclo inexistente/otro tenant/sin tenant · **422** si: ciclo `Cerrado` (RC-12), responsable inexistente/no JefeArea/Inactivo (RN-011), responsable ya asignado a otra área activa del ciclo (RN-012), ciclo al tope de áreas del plan (RN-010), o forma inválida. |
| PUT | `/api/v1/ciclos/{cicloId}/areas/{areaId}` | `[Authorize(Roles = "AdminTenant")]` | Edita nombre, comentarios y responsable. Body: `AreaUpdateRequest`. Retorna 200 con `ApiResponse<AreaResponse>`. **403** · **404** · **422** con las mismas reglas que POST (RN-012 excluyendo self). |
| PUT | `/api/v1/ciclos/{cicloId}/areas/{areaId}/desactivar` | `[Authorize(Roles = "AdminTenant")]` | Desactiva el área (CA #5): `activa = FALSE`, **sin DELETE** — los datos permanecen en solo lectura. Sin body. Retorna 200 con `ApiResponse<AreaResponse>`. **403** · **404** · **422** si el área ya está inactiva o el ciclo está `Cerrado`. |
| GET | `/api/v1/ciclos/{cicloId}/areas/responsables` | `[Authorize(Roles = "AdminTenant,Gerente")]` | Candidatos a responsable (CA #2): usuarios del tenant con `rol = 'JefeArea'` y `estado = 'Activo'`, con flag `yaAsignado` (si ya son responsables de otra área activa del ciclo). Retorna `ApiResponse<List<ResponsableCandidatoResponse>>`. **404** si el ciclo no existe/otro tenant/sin tenant. *Puente hasta HU-010.* |

> **Nota de ruteo:** `areas/responsables` (segmento literal) no colisiona con `areas/{areaId:guid}` (constraint `:guid`).

## Lógica BLL (paso a paso)

Nuevo servicio `PE-GOL.BLL/Services/AreaService.cs` + `PE-GOL.BLL/Interfaces/IAreaService.cs`.
**Ctor aprobado por spec:** `(ICicloRepository, IPlanService, TenantContext)` + overload `(..., ILogger<AreaService>?)` — patrón D13 (UsuarioService/EmpresaService/CicloService, RNF-023).
**Constantes:** `RolAdminTenant = "AdminTenant"`, `RolJefeArea = "JefeArea"`, `EntidadAuditoria = "Area"`, `JsonOpcionesAuditoria` con `UnsafeRelaxedJsonEscaping` (ADR-003).
**Helpers privados:** `ObtenerTenantIdOThrow()` (D17: null → `NotFoundException` 404), `NormalizarNombre()` (trim + colapso de espacios, mismo helper que TenantService/CicloService), `SerializarArea()`/`SerializarSnapshot()` (auditoría ADR-003).

### 1. `ListarAsync(Guid cicloId, CancellationToken ct)`
1. `tenantId = ObtenerTenantIdOThrow()` → 404 si null (D17).
2. Ciclo existe: `_repository.ObtenerPorIdAsync(tenantId, cicloId, ct)` → null → 404 (el filtro por tenant evita fuga).
3. `areaIdFiltro = (_tenantContext.Rol == RolJefeArea) ? _tenantContext.AreaId : null` (SEC-07).
4. `_repository.ListarAreasAsync(tenantId, cicloId, areaIdFiltro, ct)` (DAL-A3) → `List<AreaResponse>` (mapeo directo, sin cálculos).

### 2. `ObtenerPorIdAsync(Guid cicloId, Guid areaId, CancellationToken ct)`
1. `tenantId = ObtenerTenantIdOThrow()` → 404.
2. Ciclo existe → 404.
3. `_repository.ObtenerAreaPorIdAsync(tenantId, cicloId, areaId, ct)` (DAL-A2) → null → 404.
4. **D12/SEC-07:** si `_tenantContext.Rol == RolJefeArea` y `area.Id != _tenantContext.AreaId` → `AccesoDenegadoException` (403).
5. Mapear → `AreaResponse`.

### 3. `CrearAsync(Guid cicloId, AreaCreateRequest request, CancellationToken ct)`
1. **D12:** `_tenantContext.Rol != RolAdminTenant` → `AccesoDenegadoException` (403).
2. `tenantId = ObtenerTenantIdOThrow()` → 404.
3. Ciclo existe → 404.
4. **RC-12:** `ciclo.Estado == "Cerrado"` → `ValidacionException` (422) "Un ciclo Cerrado es de solo lectura". *(Borrador y Activo permitidos — Flag #4.)*
5. `nombre = NormalizarNombre(request.Nombre)`.
6. **Responsable (CA #2, RN-011):** `_repository.ObtenerResponsableAsync(tenantId, request.ResponsableId, ct)` (DAL-A9) → null → 422 "El responsable no existe en el tenant"; `rol != JefeArea` → 422; `estado != Activo` → 422.
7. **RN-012 (CA #3):** `_repository.ContarAreasConResponsableAsync(tenantId, cicloId, request.ResponsableId, null, ct)` (DAL-A8) `> 0` → 422 "El responsable ya está asignado a otra área activa de este ciclo".
8. **Límite de áreas (CA #4, RN-010):**
   a. `planId = _repository.ObtenerPlanIdDelTenantAsync(tenantId, ct)` (DAL-C8, ya existe) → null → 404 "El tenant no tiene un plan asignado".
   b. `limites = _planService.ObtenerLimitesAsync(planId, ct)` (**NUEVO método IPlanService** — Flag #2) → `PlanLimits`.
   c. **Chequeo preciso por ciclo:** `_repository.ContarAreasActivasEnCicloAsync(tenantId, cicloId, ct)` (DAL-A6) `>= limites.MaxAreas` → 422 $"El ciclo ya alcanzó el límite de áreas del plan ({limites.MaxAreas})". *(El chequeo por MAX-per-ciclo de DAL-P8 con comparación estricta `>` NO detecta el caso "ciclo objetivo al tope" — ver § Flags #2.)*
   d. **Guarda a nivel tenant (CA #2 HU-002, HANDOFF L181):** `resultado = _planService.ValidarLimitesParaTenantAsync(tenantId, planId, ct)` → `!resultado.EsValido` → 422 `string.Join(" ", resultado.Errores)` (mismo patrón que `CicloService.ActivarAsync` L297-299 y `UsuarioService` HU-003).
9. **Código GOL (CA #1, DB-04 — se calcula en BLL):** `siguiente = _repository.ObtenerSiguienteOrdenAsync(tenantId, cicloId, ct)` (DAL-A7: `MAX(orden)+1` sobre TODAS las áreas del ciclo, incl. inactivas → sin reutilizar códigos tras desactivar) → `codigo = $"GOL{siguiente}"`, `orden = siguiente`.
10. **Transacción única** (`BeginTransactionAsync`, patrón HU-001..008):
    - `nuevoId = _repository.InsertarAreaAsync(new AreaInsertDto { TenantId, CicloId, Codigo, Nombre, Comentarios, ResponsableId, Orden, Activa = true }, tx, ct)` (DAL-A1) → null → `InvalidOperationException`.
    - **Sync SEC-07 (D-J):** `_repository.ActualizarAreaIdUsuarioAsync(request.ResponsableId, nuevoId, tx, ct)` (DAL-A11) — `usuario.area_id = @AreaId` para que el JWT claim `area_id` del JefeArea coincida con su asignación (Flag #5).
    - Auditoría: `_repository.InsertLogAsync(new LogAuditoriaInsert { TenantId, UsuarioId = _tenantContext.UserId, Accion = "CREATE", Entidad = "Area", EntidadId = nuevoId.ToString(), ValorAnterior = null, ValorNuevo = SerializarArea(...) }, tx, ct)` (DAL-C11 reutilizada, ADR-003).
    - `tx.Commit()`.
11. Re-lectura post-commit (DAL-A2) → 201 `AreaResponse`.
12. `catch (PostgresException ex) when (ex.SqlState == "23505")` → rollback explícito + 422 "Ya existe un área con el código 'GOLn' en este ciclo" (capa 2 BD del `UNIQUE (ciclo_id, codigo)` — patrón ADR-001). `catch` general → rollback + rethrow.

### 4. `ActualizarAsync(Guid cicloId, Guid areaId, AreaUpdateRequest request, CancellationToken ct)`
1. **D12:** rol ≠ ADM → 403.
2. `tenantId = ObtenerTenantIdOThrow()` → 404.
3. Ciclo existe → 404.
4. `original = _repository.ObtenerAreaPorIdAsync(tenantId, cicloId, areaId, ct)` (DAL-A2) → null → 404.
5. **RC-12:** ciclo `Cerrado` → 422.
6. `nombre = NormalizarNombre(request.Nombre)`.
7. **Responsable (RN-011):** DAL-A9 → validaciones igual que Crear (paso 6).
8. **RN-012 excluyendo self:** `_repository.ContarAreasConResponsableAsync(tenantId, cicloId, request.ResponsableId, areaId, ct)` (DAL-A8 con `excludeAreaId = areaId`) `> 0` → 422.
9. **Transacción única:**
    - `_repository.ActualizarAreaAsync(new AreaUpdateDto { Id = areaId, TenantId, CicloId, Nombre, Comentarios, ResponsableId }, tx, ct)` (DAL-A4).
    - **Sync SEC-07 (D-J) si cambia el responsable** (`request.ResponsableId != original.ResponsableId`):
      - Si `original.ResponsableId` no es null → `_repository.ActualizarAreaIdUsuarioAsync(original.ResponsableId.Value, null, tx, ct)` (DAL-A11 con `areaId = null` — libera al responsable anterior; evita fuga de acceso SEC-07).
      - `_repository.ActualizarAreaIdUsuarioAsync(request.ResponsableId, areaId, tx, ct)` (DAL-A11).
    - Auditoría UPDATE con snapshot: `ValorAnterior = SerializarSnapshot(original)`, `ValorNuevo = SerializarArea(...)` (ADR-003).
    - `tx.Commit()`.
10. Re-lectura post-commit → 200.
11. Captura 23505 → 422 (mismo patrón que Crear).

### 5. `DesactivarAsync(Guid cicloId, Guid areaId, CancellationToken ct)`
1. **D12:** rol ≠ ADM → 403.
2. `tenantId = ObtenerTenantIdOThrow()` → 404.
3. Ciclo existe → 404.
4. `area = _repository.ObtenerAreaPorIdAsync(...)` → null → 404.
5. **RC-12:** ciclo `Cerrado` → 422.
6. `!area.Activa` → 422 "El área ya está desactivada".
7. **Transacción única:**
    - `_repository.DesactivarAreaAsync(tenantId, cicloId, areaId, tx, ct)` (DAL-A5: `UPDATE area SET activa = FALSE, updated_at = NOW()`).
    - Auditoría: `Accion = "DEACTIVATE"` (existe en `accion_auditoria` L46), `ValorAnterior = SerializarSnapshot(area)`, `ValorNuevo = SerializarArea(..., activa: false)`.
    - `tx.Commit()`.
8. Re-lectura post-commit → 200.
9. **NO se limpia `usuario.area_id`** (D-J): el JefeArea conserva acceso de **solo lectura** a los datos de su área desactivada (CA #5: "sus datos permanecen en solo lectura"; la RLS `area_tenant_policy` permite `id = auth.area_id()` sin importar `activa`). Flag #5.

### 6. `ListarResponsablesCandidatosAsync(Guid cicloId, CancellationToken ct)`
1. `tenantId = ObtenerTenantIdOThrow()` → 404.
2. Ciclo existe → 404.
3. `_repository.ListarResponsablesCandidatosAsync(tenantId, cicloId, ct)` (DAL-A10) → `List<ResponsableCandidatoResponse>` (usuarios `JefeArea` + `Activo` del tenant, con `yaAsignado` calculado en SQL como EXISTS de área activa del ciclo con ese responsable).

### 7. Extensión de `CicloService.ClonarAsync` (CA #5 HU-007 — backlog L197)
En `PE-GOL.BLL/Services/CicloService.cs`, dentro de la transacción existente de `ClonarAsync` (tras copiar umbrales, antes del commit):
1. `areasOrigen = (await _repository.ListarAreasAsync(tenantId, idOrigen, null, ct)).ToList()` (DAL-A3 sin filtro de área — todas, activas e inactivas).
2. Para cada área origen:
   - `nuevoAreaId = await _repository.InsertarAreaAsync(new AreaInsertDto { TenantId, CicloId = nuevoId, Codigo = a.Codigo, Nombre = a.Nombre, Comentarios = a.Comentarios, ResponsableId = a.ResponsableId, Orden = a.Orden, Activa = a.Activa }, tx, ct)` (DAL-A1 — se copia `activa` tal cual).
   - Auditoría CREATE por área: `InsertLogAsync(..., Accion = "CREATE", Entidad = "Area", EntidadId = nuevoAreaId.ToString(), ValorAnterior = null, ValorNuevo = SerializarArea(...))` (ADR-003).
   - **Sync SEC-07 (D-J):** si `a.ResponsableId` no es null → `_repository.ActualizarAreaIdUsuarioAsync(a.ResponsableId.Value, nuevoAreaId, tx, ct)` (DAL-A11) — el JefeArea pasa a operar sobre el área del ciclo nuevo (Flag #5).
3. El `ValorNuevo` de la auditoría CREATE del ciclo incluye `areasClonadas = areasOrigen.Count` (trazabilidad D11).
4. Defensivo: si el origen no tiene áreas (0 filas), no se inserta nada (el ciclo nuevo queda sin áreas; el ADM las crea — RN-010 permite 1..N).
> **Sin cambios de firma** en `ICicloService.ClonarAsync` (el contrato queda igual; solo se extiende la implementación).

## Queries DAL

Implementación en `PE-GOL.DAL/Repositories/Ciclo/CicloRepository.cs` + `PE-GOL.DAL/Interfaces/ICicloRepository.cs` (se **extiende**; no se crea repositorio nuevo — las áreas son hijos del agregado Ciclo, mismo criterio que `UmbralSemaforo` en HU-008). Solo Dapper + SQL parametrizado (STACK-03, SEC-05). **Toda query incluye `WHERE tenant_id = @TenantId` como primera condición** (SEC-06). **SEC-07:** `area` SÍ es entidad de área → `AND id = @AreaId` cuando el rol es `JefeArea` (parámetro `areaIdFiltro` que la BLL pasa desde `TenantContext.AreaId`). RLS `area_tenant_policy` (06 L511-518) — doble capa.

| ID | Método | SQL (parametrizado) |
|----|--------|---------------------|
| DAL-A1 | `InsertarAreaAsync(AreaInsertDto, tx, ct)` | `INSERT INTO area (tenant_id, ciclo_id, codigo, nombre, comentarios, responsable_id, orden, activa) VALUES (@TenantId, @CicloId, @Codigo, @Nombre, @Comentarios, @ResponsableId, @Orden, @Activa) RETURNING id;` |
| DAL-A2 | `ObtenerAreaPorIdAsync(Guid tenantId, Guid cicloId, Guid areaId, ct)` | `SELECT a.id, a.tenant_id, a.ciclo_id, a.codigo, a.nombre, a.comentarios, a.responsable_id, u.nombre AS responsable_nombre, u.correo AS responsable_correo, a.orden, a.activa, a.created_at, a.updated_at FROM area a LEFT JOIN usuario u ON u.id = a.responsable_id WHERE a.tenant_id = @TenantId AND a.ciclo_id = @CicloId AND a.id = @AreaId;` |
| DAL-A3 | `ListarAreasAsync(Guid tenantId, Guid cicloId, Guid? areaIdFiltro = null, ct)` | Igual SELECT que A2, `WHERE a.tenant_id = @TenantId AND a.ciclo_id = @CicloId AND (@AreaIdFiltro IS NULL OR a.id = @AreaIdFiltro) ORDER BY a.orden ASC;` |
| DAL-A4 | `ActualizarAreaAsync(AreaUpdateDto, tx, ct)` | `UPDATE area SET nombre = @Nombre, comentarios = @Comentarios, responsable_id = @ResponsableId, updated_at = NOW() WHERE tenant_id = @TenantId AND ciclo_id = @CicloId AND id = @Id;` |
| DAL-A5 | `DesactivarAreaAsync(Guid tenantId, Guid cicloId, Guid areaId, tx, ct)` | `UPDATE area SET activa = FALSE, updated_at = NOW() WHERE tenant_id = @TenantId AND ciclo_id = @CicloId AND id = @AreaId;` |

No rompe tests existentes (aditivo). **Necesario** porque `ValidarLimitesParaTenantAsync` (DAL-P8, comparación estricta `>`) no detecta el caso "ciclo objetivo al tope de áreas" — el consumo de `ValidarLimitesParaTenantAsync` (CA #2 HU-002) se mantiene como guarda a nivel tenant. → **RESUELTO:** `IPlanService.ObtenerLimitesAsync` confirmado (método aditivo).
3. **RN-006 vs backlog:** RN-006 (L270) otorga al **Gerente** escritura sobre Áreas; el backlog HU-009 dice "Como **ADM**". Propuesta: escritura ADM-only (precedente D-A HU-007 aprobado por Jorge), GER lectura. **Confirmar.** → **RESUELTO:** escritura ADM-only, GER lectura; RN-006 actualizado en `02_REQUERIMIENTOS.md` con la redacción de Jorge.

Alternativa: crear/editar solo en Borrador (como umbrales RN-039) y desactivar en Activo. **Confirmar.** → **RESUELTO:** Borrador + Activo permiten crear/editar/desactivar; Cerrado solo lectura (RC-12).
