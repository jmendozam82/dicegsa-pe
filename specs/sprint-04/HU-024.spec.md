## Verificación DDL y Modelo de Datos

La especificación se alinea estrictamente con `06_MODELO_DATOS.md` (DB-01 — el DDL es la fuente de verdad):

- `okr` (L233-247): `tenant_id`, `ciclo_id`, `area_id`, `pilar_id` (UUIDs, FK) · `codigo VARCHAR(10) NOT NULL` · `descripcion TEXT NOT NULL` · `puntuacion_final DECIMAL(4,3) NOT NULL DEFAULT 0.000` (rango 0.000-1.000) · `semaforo semaforo_color NOT NULL DEFAULT 'Rojo'` (enum `'Verde'|'Amarillo'|'Rojo'`) · `orden INT NOT NULL DEFAULT 0` · `created_at`/`updated_at` TIMESTAMPTZ.
- **`UNIQUE (area_id, codigo)`** (L246) — la restricción de unicidad es **por área** (a diferencia de `objetivo_cg`, que es `UNIQUE (ciclo_id, codigo)`): encaja exactamente con «`OKR.N` secuencial por área» (CA #1) y es la capa 2 de la carrera TOCTOU (23505 → 422).
- `idx_okr_area` (L248) optimiza las búsquedas por área.
- RLS `okr_policy` (L542-549): `tenant_id = auth.tenant_id() AND (rol IN (SuperAdmin, AdminTenant, Gerente) OR area_id = auth.area_id())` — segunda capa de aislamiento (ARCH-04).
- `key_result` (L250-267): `okr_id UUID NOT NULL REFERENCES okr(id) **ON DELETE CASCADE**` (L253) — un DELETE físico del OKR arrastra sus KRs (relevante para F2).
- `valor_mensual_kr` (L269-278): la columna del valor real mensual es **`valor`** `DECIMAL(2,1) CHECK (valor BETWEEN 0.0 AND 1.0)` (L274).

> **⚠ Discrepancias del encargo vs DDL (corregidas en este spec — DB-01):**
> 1. El encargo de redacción listaba `okr(..., created_by, updated_by)`: **esas columnas NO existen** en el DDL de `okr` (L233-247). La autoría de cada cambio queda registrada en `log_auditoria` (`usuario_id`, ADR-003), no en la tabla. Este spec **no las inventa**.
> 2. El encargo nombra la tabla `area_estrategica`: la tabla real del DDL es **`area`** (L194-209). Este spec usa `area`.
> 3. El encargo nombra la columna `valor_mensual_kr.valor_real`: la columna real del DDL es **`valor`** (L274). Este spec usa `valor`.

## Flags y Decisiones Críticas (para aprobación de Jorge)

- **[F1] Permisos — escritura y lectura JEF-only en esta HU (RN-006 vs RF-033):** RN-006 da al GER lectura y escritura del contenido estratégico (incluye OKRs), pero **RF-033 nombra al Jefe de Área** como actor del CRUD de OKRs de su área y **ningún CA de HU-024 pide escritura GER**. Además, soportar escritura GER exigiría recibir `area_id` en el request (el GER no tiene área en su `TenantContext`), en fricción con SEC-06. **Propuesta (precedente exacto HU-017→HU-018 y HU-019):** los 5 endpoints de HU-024 son `[Authorize(Roles = "JefeArea")]`; la vista consolidada de OKRs del GER (RF-040) llega en **HU-027** (Sprint 5), que satisface la lectura GER de RN-006. La escritura GER de OKRs, si se desea, requiere HU propia con decisión explícita de cómo selecciona el área. **→ Confirmar.**
- **[F2] DELETE físico — bloqueo solo con valores reales (CA #3 + RN-028 literal):** la regla bloquea la eliminación **solo si algún KR del OKR tiene registros en `valor_mensual_kr`** («Primero deben borrarse los valores del período» — RN-028). Un OKR con KRs **sin** valores reales **sí se elimina**, y sus KRs caen por el `ON DELETE CASCADE` del DDL (L253). **→ Confirmar lectura literal.**
- **[F3] Puntuación y semáforo iniciales:** al crear, la BLL persiste `puntuacion_final = 0.000` y `semaforo = 'Rojo'` (patrón F4 de HU-017: progreso inicial 0 → Rojo). El recálculo con base en KRs llega en HU-026. **→ Confirmar.**
- **[F4] Secuencia del código — `MAX(regexp)+1`, NO `COUNT+1`:** el encargo pide «patrón similar a `PilarService` código PEC-N» → `MAX((regexp_match(codigo,'^OKR\.(\d+)$'))[1]::INT)+1` por área (patrón DAL-P5). **Motivo técnico:** el patrón `COUNT+1` (usado en HU-017) colisiona permanentemente tras eliminar un OKR intermedio — ej. existen `OKR.1` y `OKR.3` (se eliminó `OKR.2`): `COUNT = 2` → siguiente `OKR.3` → 23505 en bucle infinito de reintento. `MAX(N)+1` genera `OKR.4` y nunca reutiliza un código vivo. Capa 2: `UNIQUE (area_id, codigo)` → 23505 → 422. **→ Confirmar.**

| Método | Ruta | Auth | Descripción |

- Controller: `PE-GOL.API/Controllers/OkrController.cs` — `[ApiController]`, `[Route("api/v1/okrs")]`, `[Authorize]` de clase, `[Authorize(Roles = "JefeArea")]` por acción (patrón `ObjetivoCgController`).

- **ARCH-07:** todas las respuestas envueltas en `ApiResponse<T>`. Códigos por endpoint:
  - `GET` (ambos): `200` (lista vacía válida) · `401` · `403` · `404` (sin tenant/área en contexto, sin ciclo activo, o `{id}` inexistente/de otra área).

**Constantes:** `RolJefeArea = "JefeArea"` · `EntidadAuditoria = "Okr"` · `MaxOkrsPorArea = 9` (CA #5) · `MaxLongitudDescripcion = 500` (límite de negocio sobre `TEXT`, consistente con `ObjetivoCg`).

**Helpers privados (patrón `ObjetivoCgService` verbatim):**
- `ObtenerTenantIdOThrow()` — `TenantId is null` → `NotFoundException` (404).
- `ValidarPermisoEscritura()` — tenant (404) → `Rol != "JefeArea"` → `AccesoDenegadoException` (403) → `AreaId is null` → `NotFoundException` (404).
- `ObtenerCicloActivoIdAsync()` — ciclo activo o `NotFoundException` (404); sin bloqueo de estado (lecturas).
- `ObtenerCicloActivoYVerificarEstadoAsync(bool soloLectura)` — ídem + `!soloLectura && Estado == "Cerrado"` → `ValidacionException` (422, RC-12).
- `JsonOpcionesAuditoria` — `JsonSerializerOptions` con `UnsafeRelaxedJsonEscaping` (ADR-003).

### 1. Listar (`ListarAsync`) — CA #4

1. `tenantId = ObtenerTenantIdOThrow()` (404).
2. `AreaId is null o Guid.Empty` → `NotFoundException("El usuario no tiene un área asignada.")` (404).
3. `cicloId = ObtenerCicloActivoIdAsync()` (404 sin ciclo activo — RC-01). Lectura permitida con ciclo `Cerrado`.
4. `return await _repo.ListarAsync(tenantId, cicloId, areaId, ct)` — lista con `PuntuacionFinal`, `Semaforo` y `PilarNombre`, `ORDER BY orden ASC, created_at ASC`. Lista vacía es **200** válido (la UI muestra `.empty-state`, UX-05).

### 2. Obtener por id (`ObtenerPorIdAsync`)

1. Pasos 1-2 de Listar (tenant + área).
2. `okr = await _repo.ObtenerPorIdAsync(tenantId, areaId, id, ct)` — `null` → `NotFoundException("El OKR no existe o no pertenece a su área.")` (404, sin fuga de datos de otras áreas — RN-008).
3. Retornar el DTO plano; el controller envuelve en `ApiResponse<T>` (ARCH-07).

### 3. Crear (`CrearAsync`) — CA #1, CA #2, CA #5

1. `ValidarPermisoEscritura()` (403/404).
2. `cicloId = ObtenerCicloActivoYVerificarEstadoAsync(soloLectura: false)` (404/422 — RC-12).
3. **Validar pilar (CA #2):** `try { await _pilarService.ObtenerAsync(cicloId, request.PilarId, ct); } catch (NotFoundException) { throw new NotFoundException("El pilar estratégico especificado no existe en este ciclo."); }` (404 — cubre pilar de otro tenant/ciclo, sin fuga).
4. **CA #5:** `count = await _repo.ContarOkrsPorAreaAsync(tenantId, cicloId, areaId, ct)`; si `count >= MaxOkrsPorArea` → `ValidacionException("Máximo 9 OKRs por área por ciclo.")` (422). Regla blanda: carrera TOCTOU aceptada (patrón `MaxPilaresPorCiclo`, HU-013).
5. **CA #1 (F4):** `sec = await _repo.ObtenerSiguienteSecuenciaOkrAsync(tenantId, cicloId, areaId, ct)`; `codigo = $"OKR.{sec.SiguienteN}"`; `orden = sec.SiguienteOrden`.
6. **Transacción** (`using var tx = await _repo.BeginTransactionAsync(ct)`):
   1. `nuevoId = await _repo.CrearAsync(tenantId, cicloId, areaId, codigo, orden, request, tx, ct)` — INSERT con `puntuacion_final = 0.000`, `semaforo = 'Rojo'` (F3) ... `RETURNING id`.
   2. `creado = await ObtenerPorIdAsync(nuevoId)` (re-lectura dentro de la tx — misma conexión del repo).
   3. **Auditoría (ADR-003):** `await _repo.InsertLogAsync(new LogAuditoriaInsert { TenantId, UsuarioId = _tenantContext.UserId, Accion = "CREATE", Entidad = "Okr", EntidadId = nuevoId.ToString(), ValorAnterior = null, ValorNuevo = JsonSerializer.Serialize(creado, JsonOpcionesAuditoria) }, tx, ct)` — misma transacción.
   4. `tx.Commit()`; retornar `creado` (201).
7. `catch (PostgresException ex) when (ex.SqlState == "23505")` → rollback → `ValidacionException("Hubo un conflicto generando el código correlativo. Por favor intente de nuevo.")` (422 — carrera TOCTOU, capa 2 = `UNIQUE (area_id, codigo)`).
8. `catch` genérico → rollback → rethrow.

### 4. Actualizar (`ActualizarAsync`) — CA #2

1. Pasos 1-2 de Crear (permiso + ciclo con RC-12).
2. `actual = await ObtenerPorIdAsync(id)` (404 si no existe / no es de su área).
3. Si `actual.PilarId != request.PilarId` → validar el nuevo pilar (paso 3 de Crear) → 404 si no existe en el ciclo.
4. **Transacción:**
   1. `await _repo.ActualizarAsync(tenantId, areaId, id, request, tx, ct)` — UPDATE **solo** `pilar_id`, `descripcion`, `updated_at = CURRENT_TIMESTAMP`. **No toca** `codigo`, `puntuacion_final`, `semaforo`, `orden` (CA #1, DB-04).
   2. `actualizado = await ObtenerPorIdAsync(id)`.
   3. Auditoría `UPDATE`: `ValorAnterior = Serialize(actual)`, `ValorNuevo = Serialize(actualizado)` — misma tx.
   4. Commit; retornar `actualizado` (200).
5. `catch` genérico → rollback → rethrow.

### 5. Eliminar (`EliminarAsync`) — CA #3 / RN-028 / F2

1. Pasos 1-2 de Crear (permiso + ciclo con RC-12).
2. `actual = await ObtenerPorIdAsync(id)` (404).
3. **CA #3:** `tieneValores = await _repo.VerificarKrsConValoresAsync(tenantId, id, ct)`; si `true` → `ValidacionException("No se puede eliminar el OKR porque tiene KRs con valores reales registrados. Primero deben borrarse los valores del período.")` (422 — RN-028).
4. **Transacción:**
   1. `await _repo.EliminarAsync(tenantId, areaId, id, tx, ct)` — DELETE físico; los KRs sin valores caen en cascada (`ON DELETE CASCADE`, DDL L253 — F2).
   2. Auditoría `DELETE`: `ValorAnterior = Serialize(actual)`, `ValorNuevo = null` — misma tx.
   3. Commit (200).

### Query 1 — Listar (CA #4)

```sql
SELECT o.id               AS Id,
       o.ciclo_id         AS CicloId,
       o.area_id          AS AreaId,
       o.pilar_id         AS PilarId,
       p.nombre           AS PilarNombre,
       o.codigo           AS Codigo,
       o.descripcion      AS Descripcion,
       o.puntuacion_final AS PuntuacionFinal,
       o.semaforo::text   AS Semaforo,
       o.created_at       AS CreatedAt,
       o.updated_at       AS UpdatedAt
FROM okr o
INNER JOIN pilar p ON o.pilar_id = p.id
WHERE o.tenant_id = @TenantId
  AND o.ciclo_id  = @CicloId
  AND o.area_id   = @AreaId
ORDER BY o.orden ASC, o.created_at ASC;
```

### Query 2 — Obtener por id

```sql
-- Misma proyección y JOIN que la Query 1, con:
WHERE o.id        = @Id
  AND o.tenant_id = @TenantId
  AND o.area_id   = @AreaId;
-- QuerySingleOrDefaultAsync<OkrResponse> → null si no existe o es de otra área (sin fuga).
```

### Query 3 — Conteo por área (CA #5)

```sql
SELECT COUNT(1)
FROM okr
WHERE tenant_id = @TenantId
  AND ciclo_id  = @CicloId
  AND area_id   = @AreaId;
```

### Query 4 — Siguiente secuencia (CA #1, F4 — patrón DAL-P5 de HU-013)

```sql
SELECT COALESCE(MAX((regexp_match(codigo, '^OKR\.(\d+)$'))[1]::INT), 0) + 1 AS SiguienteN,
       COALESCE(MAX(orden), 0) + 1                                        AS SiguienteOrden
FROM okr
WHERE tenant_id = @TenantId
  AND ciclo_id  = @CicloId
  AND area_id   = @AreaId;
```

> `regexp_match` extrae el `N` solo de filas con formato exacto `OKR.<dígitos>` (defensivo); `COALESCE(..., 0) + 1` arranca en `OKR.1` cuando el área no tiene OKRs. **Nunca reutiliza un código vivo** tras eliminaciones intermedias (F4).

### Query 5 — Verificar KRs con valores reales (CA #3 / RN-028)

```sql
SELECT EXISTS(
    SELECT 1
    FROM key_result kr
    WHERE kr.okr_id    = @OkrId
      AND kr.tenant_id = @TenantId
      AND EXISTS (SELECT 1 FROM valor_mensual_kr vmk WHERE vmk.key_result_id = kr.id)
);
```

> El `okr_id` ya fue verificado como perteneciente al área del JEF en el paso 2 de `EliminarAsync` (doble compuerta); el EXISTS anidado detecta **cualquier** KR del OKR con al menos un valor real registrado.

### Query 6 — Insertar (con RETURNING id)

```sql
INSERT INTO okr (tenant_id, ciclo_id, area_id, pilar_id, codigo, descripcion, puntuacion_final, semaforo, orden)
VALUES (@TenantId, @CicloId, @AreaId, @PilarId, @Codigo, @Descripcion, 0.000, 'Rojo'::semaforo_color, @Orden)
RETURNING id;
-- Parámetros: @PilarId = request.PilarId, @Descripcion = request.Descripcion (los demás llegan de la BLL).
```

### Query 7 — Actualizar

```sql
UPDATE okr
SET pilar_id    = @PilarId,
    descripcion = @Descripcion,
    updated_at  = CURRENT_TIMESTAMP
WHERE id        = @Id
  AND tenant_id = @TenantId
  AND area_id   = @AreaId;
```

### Query 8 — Eliminar (físico)

```sql
DELETE FROM okr
WHERE id        = @Id
  AND tenant_id = @TenantId
  AND area_id   = @AreaId;
```

### Query 9 — InsertLog (auditoría, patrón ADR-003)

```sql
INSERT INTO log_auditoria (tenant_id, usuario_id, accion, entidad, entidad_id, valor_anterior, valor_nuevo)
VALUES (@TenantId, @UsuarioId, @Accion::accion_auditoria, @Entidad, @EntidadId, @ValorAnterior::jsonb, @ValorNuevo::jsonb);
```

**Todas las queries:** `WHERE tenant_id = @TenantId` como primera condición de aislamiento (SEC-06) + `AND area_id = @AreaId` en toda entidad de área (SEC-07 — incluidas UPDATE/DELETE, ver «Decisiones técnicas clave») · parámetros nombrados Dapper (SEC-05) · sin concatenación de strings SQL · enums PostgreSQL con cast `::text` / `::semaforo_color` / `::accion_auditoria` (patrón existente).
